## 快速部署

需要服务器安装 Docker Engine 与 Compose 插件。以下在项目根目录执行：

```bash
python3 scripts/init.py
docker compose up -d --build
docker compose ps
```

初始化脚本创建 `.env`，含随机数据库密码、APP_SECRET、SETUP_TOKEN，不会覆盖已有文件。
安全地在服务器本地读取 `.env` 中的 `SETUP_TOKEN`，不要把该文件提交到Git或分享。

应用仅绑定 `127.0.0.1:8080`。可先通过 SSH 隧道测试：

```bash
ssh -L 8080:127.0.0.1:8080 your-user@your-server
```

打开 `http://localhost:8080`，填写安装令牌、管理员用户名和至少12位密码。
安装完成后进入“管理后台”。安装接口不能再创建管理员。

## 域名与HTTPS

1. 将 `tarot.opsglobalonline.com` 解析到服务器。
2. 按现有证书流程申请TLS证书。
3. 参考 `nginx.conf.example` 配置宿主机Nginx反向代理。
4. 将 `.env` 的 `COOKIE_SECURE=1`（如域名不同，同时设置 `SITE_URL=https://你的域名`），然后运行：

```bash
docker compose up -d --force-recreate app
```

HTTP本地测试用 `COOKIE_SECURE=0`；公开HTTPS上线必须为1。
不要将PostgreSQL端口暴露到公网。

## 首次后台配置顺序

1. 品牌与营业：工作室名称、定位、默认时区（已设Asia/Kuala_Lumpur）。
2. AI模型：Base URL默认 `https://api.deepseek.com`，模型名按用户提供设为 `deepseek-flash`，密钥留空。
3. 点击“检测已保存配置的可用模型”。模型名称尚未经真实账户验证，可修改为服务商实际返回的ID。
4. 配置输入和输出单价，单位均为人民币/百万Token。未填正数前禁用生成，避免30元预算形同虚设。
5. 联系方式：账号、链接、二维码HTTPS图片地址、说明和启用开关。
6. 真人套餐：确认中英文说明、交付时限、追问、取消规则、占用分钟数与价格。示例默认不构成已确认服务承诺。
7. 免费试运行；需要收费时再配置收款渠道并启用开关。

### 使用 `.env` 配置 DeepSeek（推荐生产环境）

也可完全不在后台浏览器保存模型密钥。在 `.env` 中配置下面变量后，环境变量优先于后台设置；API Key 不会返回到前端，也不会写入数据库：

```dotenv
AI_API_KEY=你的DeepSeek_API_Key
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-flash
AI_DAILY_BUDGET=30
AI_USER_DAILY_LIMIT=5
AI_INPUT_PRICE=2.2
AI_OUTPUT_PRICE=8.8
AI_MAX_TOKENS=2200
```

应用配置后运行 `docker compose up -d --force-recreate app` 使变量生效。不要向浏览器、聊天群或日志粘贴 API Key。

`deepseek-flash` 在本项目中以非思考模式生成面向用户的解读，避免隐藏推理占满输出额度；如服务商以 `length` 结束但已经返回可见文字，系统会保存该结果而不会丢弃原报告。

API参考来源：https://api-docs.deepseek.com/ （OpenAI兼容接口；具体模型和单价请以你的账户为准。）

## 预算与任务机制

- 按Asia/Kuala_Lumpur日期计算每日预算，默认人民币30元，每用户5次模型调用。
- 每次生成按输入UTF-8字节保守估算输入Token、按最大输出Token预占金额。追问同样计入预算。
- 服务商返回usage后按后台单价结算；失败或usage缺失则保留预占金额，不假装知道实际费用。
- 该预算是按你配置单价计算的本地上限，不是服务商账单保证；价格变化需更新配置，建议服务商侧也设置限额。
- 同一会话生成中重复点击返回同一任务，不重复预占。
- 任务保存在数据库；排队任务可恢复。中断的运行任务在5分钟后标记失败，用户可以使用原牌重试。
- 默认一个后台执行线程串行调用模型，适合低流量MVP；不承诺高并发实时响应。
- 必须使用Compose默认的 **一个Gunicorn worker、一个app副本**。内存互斥锁保证业务状态变更原子性；多副本上线前须改为数据库行锁/任务队列。

## 数据库后台配置

数据库是保存后台账号和设置的基础，首次启动必须有可连接数据库。Compose已经自动创建，无需手动建库。

后台“数据库”支持显示当前驱动/主机/库名，测试新的PostgreSQL连接，并加密暂存。
只允许验证同一实例标识的数据库，防止切到空库丢失账号、订单和密钥。

维护期间应用已暂存配置：

```bash
docker compose exec -T app python -m scripts.apply_database
docker compose restart app
```

连接格式：`postgresql+psycopg://user:password@host:5432/database`。
特殊字符密码需要URL编码。连接信息不会通过公共接口返回。

如果迁移到新数据库：停止写入，备份并恢复完整数据库到目标库（包含instance记录），测试数据，再在后台验证/暂存连接。不要只复制空表。
若新连接有问题，将app_data中的 `database.enc` 重命名保留后重启，可退回Compose环境变量连接。

## 备份与恢复

```bash
sh scripts/backup.sh
```

此脚本备份Compose内置数据库。若后台切换到外部数据库，请对目标数据库另行执行pg_dump。
必须同时安全备份 `.env` 和app_data卷；APP_SECRET用于解密后台设置，丢失后无法恢复密钥。

恢复必须在维护窗口执行，先确认备份并停止app写入。以下命令会覆盖现有库对象，仅在明确要恢复时执行：

```bash
docker compose stop app
# 将下面文件名替换为已验证的备份
docker compose exec -T db pg_restore -U tarot -d tarot --clean --if-exists < backups/your-backup.dump
docker compose start app
```

## 收款与预约约定

- 本版是人工收款，不包含各平台商户接口、链上自动确认或自动退款。
- 用户提交交易流水/哈希和文字说明；管理员核实到账后确认，不凭文本自动放行。
- 一个站点当前采用一种结算币种；仅启用支持该币种的渠道。不同币种换算、汇率锁定是后续功能。
- TRC20必须明确资产（如USDT）、网络和地址；不要只填“TRC20”。
- 退款按钮表示“记录已经在外部完成的退款”，不会实际转账。
- 关闭收费后禁止新付款提交；原付费权益保留。已创建待付款会话可在免费模式重新创建。
- 真人服务为先申请、后确认时间、再支付（如启用收费），由工作室人工联系。
- 确认预约采用套餐的占用分钟数防止重叠；文字套餐也需设置合理的内部占用时段。
- 无人处理的待付款时段需要管理员取消释放；自动过期和提醒不在本版。
- 无外部联系渠道时，用户仍可提交站内预约并回到“我的记录”查看状态。
